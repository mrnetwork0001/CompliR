# ERC-8004 identity for CompliR (C16)

[ERC-8004 "Trustless Agents"](https://eips.ethereum.org/EIPS/eip-8004) gives every agent an ERC-721 identity in a
per-chain `IdentityRegistry`; the token URI (`agentURI`) points to a registration JSON that lists the agent's services.
Registering CompliR makes it discoverable to other agents on Arc (APEX's Watchtower, for example, calls every agent in
the Arc registry hourly).

The mainnet IdentityRegistry address is the same CREATE2 singleton used on Ethereum, Base, Polygon etc.

(`ERC8004_IDENTITY_REGISTRY`) in case Arc redeploys.

## Registering

```solidity
function register(string agentURI) external returns (uint256 agentId);   // emits Registered(agentId, agentURI, owner)
function setAgentURI(uint256 agentId, string newURI) external;             // update later
```

Steps:

1. `PUBLIC_BASE_URL=https://<prod host>` in `.env.local`. The metadata template is `scripts/erc8004/agent.json`
   (`{{PUBLIC_BASE_URL}}`, `{{CHAIN_ID}}`, `{{IDENTITY_REGISTRY}}`, `{{AGENT_ID}}` are filled by the script).
2. Dry run (no key needed) — prints the built metadata path and the exact calldata:
   `npx tsx --env-file=.env.local scripts/erc8004/register.ts --print`
3. Host the metadata. Two options:
   - **HTTPS** (default): serve `scripts/erc8004/agent.built.json` at `${PUBLIC_BASE_URL}/.well-known/agent-registration.json`
     (the path the EIP uses for domain verification). *Lead: this needs a public route / static file — see report.*
   - **On-chain** (no hosting): `--data-uri` embeds the JSON as `data:application/json;base64,…` (allowed by the EIP).
4. Register: `ERC8004_OWNER_PRIVATE_KEY=0x… npx tsx --env-file=.env.local scripts/erc8004/register.ts [--data-uri]`
   (falls back to `ATTESTER_PRIVATE_KEY`; the owner wallet pays gas in USDC on Arc). The script prints the `agentId`
   from the `Registered` event.
5. Back-reference: set `ERC8004_AGENT_ID=<id>` and re-run — the script now calls `setAgentURI` with the
   `registrations[] = [{ agentId, agentRegistry: "eip155:5042:0x8004A169…" }]` field filled in.

Without a key the script prints `{chainId, to, value, data}` so the tx can be sent from any wallet (e.g. a multisig).

## Metadata format

Per the EIP's registration-v1 example and APEX's live file on Arc
(`https://apexfaucet.xyz/.well-known/erc8004.json`):

```json
{
  "type": "https://eips.ethereum.org/EIPS/eip-8004#registration-v1",
  "name": "CompliR", "description": "…", "image": "…",
  "services": [
    { "name": "web", "endpoint": "https://…" },
    { "name": "x402", "type": "x402", "endpoint": "https://…/api/v1/screen", "url": "…", "method": "POST", "price": "0.01 USDC", "network": "eip155:5042" }
  ],
  "x402Support": true, "active": true, "supportedTrust": ["reputation"],
  "registrations": [{ "agentId": 42, "agentRegistry": "eip155:5042:0x8004A169FB4a3325136EB29fA0ceB6D2e539a432" }]
}
```

Services use the EIP's `{name, endpoint}` shape; the `type/url/price` keys requested in the spec are kept as extra
members (the EIP allows additional entries). `homepage` and `capabilities` are application-defined, which the Arc
tutorial explicitly permits ("the JSON fields at that URI are application-defined").

## x402 discovery / Coinbase Bazaar

From [docs.cdp.coinbase.com/x402/seller/get-discovered](https://docs.cdp.coinbase.com/x402/seller/get-discovered) and
[/x402/bazaar](https://docs.cdp.coinbase.com/x402/bazaar.md):

- Listing is automatic, no form: the endpoint must be a public HTTPS URL, answer `402` with payment requirements in the
  `PAYMENT-REQUIRED` header, advertise an `extensions.bazaar` block (route key = explicit method + absolute path, e.g.
  `POST /api/v1/screen`, with input/output JSON schema + example; description ≤ 500 chars), pass the read-only
  validator (`valid: true`, `simulation.outcome: "accepted"`), and then **one settled payment through the CDP
  Facilitator** triggers indexing.
- **Caveat:** the Bazaar indexes payments settled by the *CDP* facilitator; CompliR settles through Circle's facilitator
  on Arc (`eip155:5042`), and Arc is not listed among the Bazaar's networks. Bazaar listing is therefore not
  guaranteed; the ERC-8004 entry + APEX's Arc x402 explorer (`https://apexfaucet.xyz/arc/x402/`) are the discoverability
  path that definitely works on Arc today. If the lead wants Bazaar too, add the `extensions.bazaar` block to the 402
  body in `src/lib/pay` (not in my scope) and settle one call via CDP on a supported network.
